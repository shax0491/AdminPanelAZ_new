# mh-app: конфиги Mihomo, Hysteria2, MTProxyL и доступ по SSH

> **IPv6 У КЛИЕНТА РАБОТАЕТ ТОЛЬКО ЕСЛИ ПРОВАЙДЕР РЕАЛЬНО ВЫДАЁТ IPv6 ИЛИ ЕСТЬ РАБОЧИЙ IPv6-ТУННЕЛЬ.**
> **IPv6 НА VPS И AAAA-ЗАПИСЬ САМИ ПО СЕБЕ IPv6 КЛИЕНТУ НЕ СОЗДАЮТ.**
> На IPv4-only подключении используется IPv4-режим; включение dual-stack на сервере этого не меняет. Отсутствие IPv6 у
> клиента не доказывает неисправность IPv4 AntiZapret.

## Что входит

| Компонент | Где | Что делает |
|---|---|---|
| builder `deploy/mh-app/build_configs.py` | DE3 (`/usr/local/lib/mh-build/`, запуск от root через sudo-хелпер) | из `templates/home.yaml` и `nodes.json` собирает `home-config.yaml` и `work-config.yaml` в `/var/www/az-lists/` |
| guard `validate()` | внутри builder, до публикации | не публикует конфиг, если в категории нет Hysteria2, есть пустая группа, дубль, висячая ссылка, цикл или Proton в группах «без Proton»; прежний конфиг остаётся |
| `mihomo -t` | builder, до публикации | вторая проверка перед выкладкой |
| роутеры | дом (Ultra), работа (Viva) | раз в 30 минут сами забирают свой файл (config-sync) и применяют без перезапуска; выбор групп сохраняется по имени узла |
| MTProxyL | узлы DE1, DE4, NL1, NL2, FI1, FR1 (у каждого свой домен) | MTProto-прокси, лендинг-заглушка и CP на том же порту |

## Hysteria2

- Hysteria2 — отдельный выход каждого узла (`<узел> | Hysteria2`), рядом с `VLESS прямой` и `VLESS Proton`; **Proton не использует**.
- В каждой пользовательской категории напрямую выбираются Hysteria2 основных узлов (DE2, DE1, DE4, NL2), без «Авто».
  Hysteria2 резервных FI1/FR1/LV1 выбираются в карточках узлов и входят в «Резерв» (он сам выбирает быстрейший, вручную в нём ничего не выбирается).
- «Без Proton» и «Фикс. выход» Proton не содержат. «ИИ» по умолчанию стоит на `DE4 | VLESS прямой`, «Google» ведёт в «ИИ».
- Групп «Исключения» и «ИИ — DE4 прямой» больше нет: их правила переведены в «Фикс. выход (стабильный IP)».

### Как проверить, какой транспорт выбран

1. zashboard роутера: карточка категории показывает выбранный выход; Hysteria2 — в списке членов группы.
2. `GET /connections` API Mihomo: в `chains` первым стоит `<узел> | Hysteria2`, дальше категория. Групповой delay и `alive=true`
   **не** доказывают, что трафик идёт через Hysteria2.
3. Если сборка не прошла guard, в выводе builder будет `ГАРД НЕ ПРОШЁЛ, не публикую: …`, а на роутерах останется прежний файл.

## Дом и работа

- **Дом:** IPv4-режим с Hysteria2; dual-stack обратно не включать без явного решения.
- **Работа:** только IPv4: `dns.ipv6: false`, правил `IP-CIDR6` нет, узел LV1 исключён (`exclude-filter: LV1`, в реестре `work:false`).
  Fortinet на работе может резать отдельные узлы: отклик leaf смотреть в zashboard именно на рабочем роутере.

## MTProxyL

- Обновление менеджера: `mtproxyl update-check`, затем `mtproxyl update --version X.Y.Z --yes --no-restart`; откат — `mtproxyl update --rollback`.
  Перед обновлением: `mtproxyl backup`. Движок (telemt) обновляется отдельно: `mtproxyl engine update`.
- Обновлять по одному узлу (сначала canary), массовых перезапусков нет. Пользователи, секреты, лимиты и shaping при обновлении сохраняются.
- Настоящие проверки: `mtproxyl availability check` (зонды из РФ: TCP, TLS, MTProto), лендинг и CP по HTTPS. `status`/«РАБОТАЕТ»
  показывает только процесс. Низкая доступность из РФ при чистом узле — это блокировка IP на пути, а не поломка: смотреть `tcpdump` SYN на порту узла.

## SSH: прямой и через прыжок

Часть провайдеров режет данные от клиента к отдельным VPS (рукопожатие TCP проходит, пакеты с данными не доходят). Признак: на узле
`tcpdump` видит SYN/ACK, но ни одного пакета с данными; `sshd` в порядке. Прямой SSH тогда не починить на сервере. Штатный обход —
`ProxyJump` через узел, до которого данные доходят (DE1/DE3):

```
Host de1-jump
    HostName <IP DE1>
    Port 22023
    IdentityFile <ключ>
Host az-<узел>
    HostName <IP узла>
    ProxyJump de1-jump
```

Это **обход, а не восстановление прямого маршрута**.

## Откат

- Builder: `/root/backups/build_configs.py.bak-*`, шаблон `/root/backups/home.yaml.bak-*`; вернуть файл и запустить builder.
- MTProxyL: `mtproxyl update --rollback`, архивы `/opt/mtproxyl/backups/`.
- Роутеры сами вернутся к предыдущему состоянию на следующем config-sync после публикации старого файла.

## Известные ограничения

- Отклик leaf на рабочем роутере с DE3 недоступен (API работы не проходит наружу).
- Нет проверенного сценария установки «с чистого листа»: production-builder на DE3 отличается от репозитория путями и секретами
  (в репозитории — копия с переменными окружения), поэтому описание «из коробки» здесь не заявляется.
