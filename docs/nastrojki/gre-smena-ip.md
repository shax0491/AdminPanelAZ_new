# Схема с двумя IP (noez GRE): что куда вводить при смене IP

Для узлов, у которых родной IP режет ТСПУ (сейчас **DE2** и **NL3**). Узел получает у хостера noez.de два «белых» IP через GRE-туннель:

- **входной IP** — на него приходят клиенты (DNS, конфиги, RU-прокси, SSH из России);
- **выходной IP** — с него узел выходит в интернет (сайты видят его);
- **родной IP** сервера остаётся только для управления: панель и SSH с DE3 (`<IP_DE3>`).

```
клиент -> входной IP -> [GRE] -> сервер -> выходной IP -> интернет
                         родной IP: только DE3 (панель, SSH, агент 9100/9101)
```

## 1. Текущие данные

| | DE2 | NL3 |
|---|---|---|
| родной IP | <РОДНОЙ_IP_DE2> | <РОДНОЙ_IP_NL3> |
| входной IP | <ВХОДНОЙ_IP_DE2> | <ВХОДНОЙ_IP_NL3> |
| выходной IP | <ВЫХОДНОЙ_IP_DE2> | <ВЫХОДНОЙ_IP_NL3> |
| имена в DNS | de2.<ДОМЕН_УЗЛОВ>, garden.<ДОМЕН_MTPROXY> -> входной | animal.<ДОМЕН_MTPROXY> -> входной |
| SSH | `ssh -p <SSH_ПОРТ_DE2> root@<ВХОДНОЙ_IP_DE2>` | `ssh root@<ВХОДНОЙ_IP_NL3>` |
| GRE-конец хостера, внутренняя сеть | <GRE_КОНЕЦ_ХОСТЕРА>, <ВНУТР_СЕТЬ_/30> (сервер .2, шлюз .1) | в `/etc/az-gre.conf` |

Ключ для входа тот же (`<ваш_ключ>`). Первый вход на новый IP: `ssh -o StrictHostKeyChecking=accept-new ...`.

## 2. Файлы на узле

| Файл | Что это |
|---|---|
| `/etc/az-gre.conf` | все параметры туннеля (правится руками) |
| `/root/az-gre.sh` | скрипт: `up`, `down`, `status`, `egress`, `close`, `open` |
| `az-gre.service` | поднимает туннель при загрузке |
| `az-gre-egress.timer` | раз в минуту заново применяет выход и редиректы портов |
| `/root/antizapret/setup` | настройки AntiZapret (`ANTIZAPRET_OUT_IP`, `VPN_OUT_IP`) |
| `/etc/az-guard.conf` | список входящих IP (`INGRESS_IPS`) |

Главные поля `/etc/az-gre.conf`:

| Поле | Значение |
|---|---|
| `GRE_LOCAL` | родной IP сервера |
| `GRE_REMOTE` | IP GRE-конца у хостера (из личного кабинета noez) |
| `GRE_INNER_IP`, `GRE_INNER_GW` | внутренняя сеть туннеля: наш адрес и шлюз |
| `GRE_IPS` | оба белых IP (вход и выход) через пробел |
| `GRE_EXIT_IP` | выходной IP |
| `GRE_SSH_OPEN_IP` | входной IP, на котором открыт SSH |
| `GRE_NATIVE_IP` | родной IP |
| `GRE_NATIVE_SSH_FROM` | кто может ходить по SSH на родной IP (DE3) |
| `GRE_SSH_PORT` | порт SSH (DE2 — <SSH_ПОРТ_DE2>, NL3 — 22) |
| `GRE_CLOSE_NATIVE=y` | закрыть клиентские порты на родном IP |
| `GRE_EGRESS_PROCS` | процессы, которые выходят с выходного IP (xray, hysteria) |
| `GRE_DNAT_TOPORTS` | порты AWG3 (51821), для них нужен DNAT вместо REDIRECT |

## 3. Если хостер выдал новые IP или поменял туннель

Делайте по порядку. Перед правкой копируйте файл: `cp /etc/az-gre.conf /etc/az-gre.conf.bak-$(date +%s)`.

**Шаг 1. На узле.**
1. Откройте `/etc/az-gre.conf` и замените новые значения: `GRE_REMOTE`, `GRE_INNER_IP`, `GRE_INNER_GW`, `GRE_IPS`, `GRE_EXIT_IP`, `GRE_SSH_OPEN_IP`.
2. В `/root/antizapret/setup` замените `ANTIZAPRET_OUT_IP` и `VPN_OUT_IP` на **выходной** IP (интерфейс `gre1` остаётся).
3. В `/etc/az-guard.conf` обновите `INGRESS_IPS`: родной, входной и выходной IP.
4. Примените: `systemctl restart az-gre && /root/az-gre.sh egress && /root/az-gre.sh close && systemctl restart antizapret`
5. Проверьте: `/root/az-gre.sh status` (должно быть «шлюз туннеля отвечает»).

Если вы сами сидите по SSH на **входном** IP, который меняете, подключайтесь через родной IP с DE3: `ssh -J root@<IP_DE3> ...`.

**Шаг 2. DNS (Cloudflare).** Домены, которые указывают на входной IP, перенаправьте на новый:
- DE2: `de2.<ДОМЕН_УЗЛОВ>` и `garden.<ДОМЕН_MTPROXY>`;
- NL3: `animal.<ДОМЕН_MTPROXY>`.

**Шаг 3. Панель (DE3).**
1. Маршрутизация -> AntiZapret -> блок «Подключение» (вкладка «OpenVPN (панель)») -> «Список remote OpenVPN» (он же в разделе «Прокси»): первым впишите новый входной IP или имя из DNS. Этот список попадает во все выдаваемые клиентам конфиги.
2. Адрес панели к агенту узла остаётся родным IP: на DE3 в `/etc/hosts` строка `<родной IP> de2.<ДОМЕН_УЗЛОВ>` (для NL3 — своя). Её менять не нужно, пока не меняется родной IP.

**Шаг 4. Mihomo (DE3).** В `/opt/mh-app/nodes.json` у узла поле `host` — это имя из DNS, не IP. Для DE2 это `garden.<ДОМЕН_MTPROXY>`. Менять нужно только если меняется имя. После правки пересоберите конфиги (через Mini App или штатный скрипт сборки).

**Шаг 5. RU-прокси.** См. раздел 4.

**Шаг 6. Проверка.** Раздел 7.

**Клиентам** при смене входного IP старые конфиги с IP внутри перестают работать, а конфиги с именем из DNS продолжают, если DNS обновлён. Поэтому в конфигах всегда используйте имя, а не голый IP. Клиентам, которые уже подключались, помогает переподключение: старый исходный порт может залипнуть в NAT.

## 4. RU-прокси (Proxmox, дом)

Схема: клиент в России -> домашний IP `<ДОМАШНИЙ_IP>` -> роутер Keenetic (пробросы) -> VM -> входной IP узла.

| Прокси | VM | Адрес назначения (панель, поле «destination») |
|---|---|---|
| RU_DE2 | 192.168.1.137 (VM104) | входной IP DE2 = <ВХОДНОЙ_IP_DE2> |
| RU_PL1 / NL2 | 192.168.1.40 (VM101) | <ВХОДНОЙ_IP_PL1_NL2> |
| RU_LV1 | 192.168.1.114 (VM109) | <ВХОДНОЙ_IP_LV1> |

**Если входной IP узла поменялся:**
1. В панели откройте прокси-узел (RU_DE2 и т.д.) и поменяйте адрес назначения на новый входной IP. Панель сама передаёт его агенту на VM, и VM переписывает свои правила (DNAT + SNAT).
2. Проверьте на VM: `iptables -t nat -S | grep DNAT | head` — везде должен быть новый IP.
3. Роутер менять не нужно: он пробрасывает порты на VM, а не на узел.

**Если сменился домашний IP или роутер:** обновите IP в конфигах клиентов (Endpoint = домашний IP:порт) и список remote.

### Пробросы на роутере Keenetic Ultra (UDP)

Роутер: Сетевые правила -> Переадресация портов. В командной строке: `ip static udp XGigabitEthernet0 <порт> <MAC VM>`, затем `system configuration save`.

| Прокси | WG / AWG 1.5 | OpenVPN | AWG 2 AZ | AWG 2 полный | AWG 3 |
|---|---|---|---|---|---|
| DE2 (.137) | 540 | 504 | 544 | 584 | 51901 |
| PL1/NL2 (.40) | 52443 | — | 53443 (**нет**) | 53080 (**нет**) | 51902 |
| LV1 (.114) | 51443 | 50443 | 54443 -> 53443 (**нет**) | 54080 -> 53080 (**нет**) | 51903 |

«Нет» — правила на роутере ещё не добавлены. Порты 9101, 9102, 9103 — это агенты VM (9103 — DE2, 9102 — LV1, 9101 — PL1/NL2); порты 22022/<SSH_ПОРТ_DE2>/22024 — SSH к VM.

Что клиент вписывает в профиль для прокси: Endpoint = `<ДОМАШНИЙ_IP>:<порт из таблицы>`.

## 5. Прямое подключение (без RU-прокси)

Клиенты вне России или те, у кого узел доступен напрямую, подключаются на имя узла:
- WG/AWG 1.5: `de2.<ДОМЕН_УЗЛОВ>:<порт из конфига>`, порты и ключи в конфиге из панели;
- OpenVPN: список remote из панели (раздел 3, шаг 3);
- VLESS/Hysteria: через подписку Mihomo (имя `garden.<ДОМЕН_MTPROXY>`).

С выходного IP узла видны только исходящие соединения; клиентам его знать не нужно.

## 6. MTProxy, Proton, IPv6

**MTProxy.** Домены `*.<ДОМЕН_MTPROXY>` -> узлы: cdn = DE1, animal = NL3 (входной IP, 443), static = LV1, force = DE3:8443, media = FI1, bigboss = DE4. На DE2 MTProxy нет. Управление: `mtproxyl` на узле (`mtproxyl status`, `mtproxyl engine update`). Движок работает в Docker (DE1, NL3, FI1, FR1, LV1) и только на DE4 как бинарник `linkbridged`. Если у MTProxy меняется IP, обновляйте только DNS-запись домена: секрет в ссылке привязан к домену, а не к IP.

**Proton.** На DE2 и других AZ-узлах: `ANTIZAPRET_WARP=2`, `VPN_WARP=2` в `/root/antizapret/setup`, ключи `PROTON_*` там же; интерфейсы `proton`, `proton-hy`. Исходящие WG-пакеты Proton (UDP 51820) не должны уходить в GRE — это уже учтено в `az-gre.sh`.
**IPv6.** `IPV6_EGRESS=proton` на DE1, DE2, DE4, NL2, FI1, FR1. На NL3 IPv6 родной: Proton-профиля там нет, нужен отдельный ключ.

## 7. Проверка после любых изменений

На узле:
- `/root/az-gre.sh status` — туннель жив;
- `curl --interface <выходной IP> https://ifconfig.co` — выход идёт через выходной IP;
- `iptables -t nat -S PREROUTING | grep gre1` — редиректы портов на `gre1`;
- `nft list table ip az_gre_close` — закрытие родного IP.

С любой машины вне России: порт открыт и по входному IP отвечает (`nc -vz <входной IP> 443`).

Из России (через домашнюю VM): `bash -c 'exec 3<>/dev/tcp/<имя>/443'`.

## 8. Аварийный возврат

- Открыть родной IP полностью: `/root/az-gre.sh open` (до перезапуска сервиса или таймера).
- Остановить туннель: `/root/az-gre.sh down`, затем `systemctl stop az-gre-egress.timer`.
- Бэкапы скрипта и конфига лежат рядом: `/root/az-gre.sh.bak-*`, `/etc/az-gre.conf.bak-*`.

## 9. Бэкапы и чистка

На узлах старые копии (старше 14 дней) чистятся вручную. Свежие `*.bak-*` оставляйте до проверки изменений.
