# AmneziaWG 3 в панели

Интерфейс `awg1` на ноде (UDP 51821, MTU считается при установке: путь − 60 − S4, в пределах 1280–1420; значение в `/etc/amnezia/amneziawg3/mtu`). Устанавливается `setup.sh` базового репозитория (раздел «AmneziaWG 3» в README там же).

## Что делает панель
- Вкладка `/awg3` (как `/awg2`): состояние инструментов (`awg`, `amneziawg-go`), интерфейсы, пиры с handshake. Только статус и мониторинг.
- Клиенты AWG 3 создаются на странице «Клиенты» (диалог создания, протокол «AmneziaWG 3», вкладка «AmneziaWG 3» в карточках). Конфиг скачивается из карточки клиента.
- Режим клиента при создании: антизапрет или полный VPN.
- Имя клиента (1–32 символа: латиница, цифры, `_`, `-`) и режим.
  - `split` — антизапрет: `10.9.0.0/24`, DNS `10.9.0.1`, `AllowedIPs` = подсеть сервера + список маршрутов антизапрета.
  - `full` — полный VPN: `10.9.1.0/24`, DNS `10.9.1.1`, `AllowedIPs = 0.0.0.0/0`.
- Скачивание `.conf` (параметры обфускации берутся с сервера), удаление клиента (пир снимается с интерфейса и из конфига) — из карточки клиента.
- Готовые списки маршрутов для роутеров: `keenetic-amneziawg3-routes.txt` и `mikrotik-amneziawg3-routes.txt` в настройках выдачи конфигов (генерирует `parse.sh`, шлюз сервера `10.9.0.1`).
- Telegram-бот: `/awg3` (только админ, при включённом фичефлаге).

## API
- `GET /api/awg3/health`, `GET /api/awg3/monitoring`
- Клиенты: через общий `/api/configs` с `vpn_type = "amneziawg3"` и полем `awg3_mode` (`split` или `full`); скачивание — `/api/configs/{id}/download` (для AWG 3 отдаётся `awg3-<имя>.conf`), удаление — `DELETE /api/configs/{id}`.
- Отдельные клиентские эндпоинты `/api/awg3/clients` доступны для диагностики: `GET`, `POST` с телом `{"name": "...", "mode": "split" | "full"}`, `GET /api/awg3/clients/{name}/config`, `DELETE /api/awg3/clients/{name}`.

Все вызовы идут через адаптер активной ноды: локальный адаптер (нода = сервер панели) или удалённый — запросом к агенту ноды.

## Агент ноды
Эндпоинты `/awg3/*` в `backend/node_agent/main.py` требуют на ноде:
- `AWG3_ENDPOINT_HOST` — необязательно: адрес в клиентских конфигах (например, `de2.example.com`). По умолчанию берётся из `/etc/amnezia/amneziawg3/server_host`, который пишет `setup.sh`;
- `AWG3_SPLIT_ALLOWED_FILE` — необязательно: свой список маршрутов антизапрета. По умолчанию `/etc/wireguard/ips`, тот же файл, что у AWG 2.

## Хранение
- Клиенты, их ключи и PSK: `/etc/amnezia/amneziawg3/clients.json` на ноде, права 600. Пиры дублируются в `awg1.conf`, чтобы сохраняться после перезапуска `awg3@awg1`.
- Ключи в БД панели не хранятся.

## Ограничения
- Клиентские приложения AmneziaWG 2 не принимают конфиги 3.x. Сейчас это роутеры (OpenWrt с `amneziawg` 3.x, KeeneticOS 5.2+).
- Фиктивные адреса антизапрета (198.18/15) работают только через туннель и только для доменов из списка антизапрета.

## Проверка
