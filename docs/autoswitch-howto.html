01 Идея в двух словах

Пул из нескольких VPN-серверов с нативным AmneziaWG 2.0. Один падает — клиент продолжает работать через другой, без ручных действий. Работает только для AmneziaWG 2.0 — OpenVPN и WireGuard/AmneziaWG 1.5 эта система не касается вообще.

Если нет причины иначе — выбирай «На фронт-сервере»: проще для клиента, без стороннего софта, уже обкатано на практике.

03 Порядок установки с нуля режим: На фронт-сервере

1
Минимум 2 узла типа «VPN» с установленным нативным AmneziaWG 2.0 (через client.sh на самих серверах — панель это не ставит).
Проверить: страница «AmneziaWG 2.0» → статус «Готов» на каждом.
2
1 узел типа «Прокси» — фронт. Может быть отдельным сервером или тем же самым, что и один из VPN-узлов.
root@front:~
cd /opt/AdminPanelAZ
sudo ./install.sh --proxy-only --with-systemd -y
Затем добавить в панели: Узлы → Добавить узел → тип «Прокси» (host/port/ключ показывает установщик).
Проверить: узел «В сети», тип «Удалённый», транспорт HTTP.
3
Включить модули (если ещё нет): Настройки → Разделы панели → «Прокси-узлы» и «Автопереключение (пулы серверов)».
Список включённых модулей грузится в браузере один раз при открытии — после включения обнови страницу (F5), иначе пункт меню не появится.
4
Создать пул: Автопереключение → «Новый пул» → стратегия «На фронт-сервере».
5
Добавить участников: первым — узел, чей текущий рабочий AWG2-конфиг станет основой (источник identity), дальше — по приоритету.
6
Назначить фронт: узел-«Прокси» + порт. Порт — это ListenPort интерфейса antizapret2 на основном узле (см. /etc/amneziawg/antizapret2.conf).
7
Клонировать identity на каждый узел, кроме основного. Копирует ключ сервера, обфускацию и всех клиентов с основного узла.
Проверить: бейдж «identity склонирована», без ошибок.
8
«Проверить и переключить» — панель ставит DNAT на фронте, указывающий на приоритетный здоровый узел.
root@front:~
iptables -t nat -L PREROUTING -n -v | grep <порт>
# счётчик пакетов должен расти при живом трафике
9
Раздать клиенту конфиг со страницы «Клиенты» (интерфейс antizapret2). Его Endpoint должен указывать на фронт. Если фронт = основной узел — конфиг уже верный. Если фронт отдельный — поправить Endpoint вручную.

04 Добавление новых серверов

Порядок не важен, схема не меняется от того, сколько уже добавлено:

  1. На новом сервере — обычный AntiZapret + нативный AWG2 (вне панели, как обычно).
  2. На нём же — node_agent: sudo ./install.sh --node-only --with-systemd -y.
  3. Добавить в панель как узел типа «VPN».
  4. Добавить участником в нужный пул.
  5. «Клонировать identity» на него.

Второй фронт заводить не нужно — один фронт обслуживает несколько узлов и, в принципе, несколько разных пулов.

06 Известные ограничения

  • Только AmneziaWG 2.0 — OpenVPN и WG/AWG 1.5 не покрываются вообще.
  • Health-check не по расписанию — «Проверить и переключить» это кнопка, не фоновая задача. Автоматический failover без нажатия пока не запущен по крону.
  • Health-check с одной точки зрения — панель видит здоровье со стороны узла, не конкретного клиента. Сервер, заблокированный только для одного региона, но живой сам по себе, панель не отличит.
  • Локальный узел не проверяется по сети — если фронт совпадает с локальным узлом панели, «упасть» и быть обнаруженным по health-check он не может: панель ходит к себе в процессе.
  • Endpoint в обычном клиентском конфиге указывает на узел, с которого скачан, не на фронт — при отдельном фронте править вручную (шаг 9).

07 Что нашли и починили 15.09.2026

  • DESTINATION принимал только IP, а узлы регистрируются доменом/локально — добавлен резолвинг перед переключением.
  • Клонирование identity молча «успевало», хотя применение к живому интерфейсу падало — теперь ошибка не прячется.
  • awg-quick strip искал файл не там, где он лежит (реальная причина ошибки does not exist) — теперь передаётся полный путь.
  • Health-check не отличал «агент ответил» от «AWG2 реально жив» — теперь пул проверяет именно интерфейс.
  • Главная находка — conntrack. Уже установленное соединение клиента ядро держит на старом маршруте до ~180 сек, игнорируя новое DNAT-правило, пока запись не сбросится. Панель теперь сбрасывает её сама при каждом переключении — подтверждено: реальный Android-клиент переключился между PL2 и LV1 в пределах одного keepalive (~15–30 сек), без единого действия на телефоне.
  • Вторая находка — коллизия маршрутов, если на резервном узле уже стоял другой WireGuard-совместимый VPN на той же подсети (например старая установка AmneziaWG 1.5 до этого форка). Хендшейк после клонирования identity проходил нормально (это отдельный UDP-обмен), а весь обратный трафик клиента молча терялся — ядро отдавало предпочтение чужому маршруту на тот же /24. Обнаружено вживую на резервном узле с параллельной установкой. setup.sh/client.sh теперь сами добавляют точный /32-маршрут на каждого пира, который всегда побеждает /24 — без переноса подсети и без разрыва других сервисов на узле.

08 Расформировать фронт

Кнопка «Расформировать фронт» в карточке пула снимает DNAT-правило с фронт-узла и отвязывает его от пула. Участники, склонированная identity и привязанные клиенты не трогаются — фронт можно назначить заново (тот же узел или другой) в любой момент.
